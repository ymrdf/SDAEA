# 持续同场竞争生存实验

用户授权：可自由调整 CNN/全连接层、视觉分辨率、记忆大小/开关/位置、环境方块数量与机器人数，持续实验直到获得较好生存能力。每40分钟仅做最基本检查：状态、日志修改时间、进程是否存活；未完成且正常时仅一句话汇报进度，不分析中间结果，完成后再分析并启动下一轮。

## 工作记录与入口

- `campaign.json`：当前轮次、运行目录、完成的轮次。
- `round01.json`：16 机器人配置；同一 Godot 场景内同时行动/竞争，独立策略、记忆和更新。
- 运行器：`run_survival_search.py`。`--variants` 指向 JSON 数组。每个条目含 `label`、`config`，可选 `role=frozen/random`、`checkpoint`、`clear_memory`（仅冻结消融）。
- 不传 checkpoint 的学习模型继承旧 96/256/3 匹配的视觉/全连接权重。新增记忆和 CNN 参数是新初始化，不能声称初始策略相同。
- 每次使用全新运行目录，快照保存源码和参数。已有结果不得覆盖。

## 第一轮

12 个学习机器人：无记忆；64/256/512 维 FC1 记忆；FC2/FC3 接入；16 次决策训练窗口；额外一层 stride-1 CNN；48/144 输入；512 宽度；关闭资格迹但保留时间反传。
另有两只冻结旧模型、两只纯随机机器人。
源：`runs/competition_20260929_small/96_w256_d3/latest.pt`。
场景种子 29，模型初始化种子 29+i。相机 160×150。初始和补充目标均 60 绿/200 红；相对先前最低 50 绿略增，并记录到 plan。
每阶段所有身体重置 HP6，循环状态/视觉 EMA/资格迹清空。资源和世界在阶段间继续演化。
流程：5000 步初始冻结评估 → 50000 步共同在线训练 → 50000 步共同冻结评估。
前后评估长度不同，比较死亡率而非直接比较死亡总数。

## 判断与后续迭代

先依据最终冻结结果筛选，比较随机/旧模型的死亡率、真实绿块获取、红块碰撞、最长及截尾寿命、初始/最终 HP、无加速比例。不把短窗零死亡、训练尾部高 HP 或一次幸运开局当成成功。
优胜者必须另开冻结验证：从 HP6 起步，至少 3 个新世界种子，包含随机、旧模型和清空循环记忆消融，在每个世界内同时竞争。可使用同一运行器，设置 `--initial-eval-steps 0 --train-steps 0 --eval-steps 50000`，所有非随机条目标记 frozen，并传各自 checkpoint。

暂定验收目标（操作性标准，不保证必能达到）：跨 3 个新世界种子的平均死亡率至少比随机和旧冻结模型低 50%；至少 2 个世界中出现单次连续存活 50000 步，并实际获取绿块补给；进一步用另一训练种子复现改善。若随机同样容易无限生存或所有机器人死亡为零，环境不具区分度，不判成功。改简单环境形成课程后，还需返回原难度验证。

未达标时自主选择下一轮：继续训练优胜者、检查策略熵/更新幅度/TD，针对性调整容量、时间窗口、学习参数，或课程难度；不要只机械加宽加深。优先少量有解释力的改动。记录配置选择理由和训练预算。每轮保留同场随机/冻结参照。
训练参数的 body-only 原则不变：方块真实计数、物体坐标等诊断标签不输入模型、不用于额外奖励。长期状态由可训练循环记忆提供。

## 性能与恢复

GPU 时间窗口 CNN 和非循环 FC 已批处理；资格迹参数更新使用 foreach；冻结评估直接推进循环状态，不重算整个训练窗口。各机器人更新目前仍按 Python 循环调用，并未实现跨机器人批处理。
16 机器人短测：200 训练步从 65.35 秒降至 45.59 秒；40 步冻结评估从 9.13 秒降至 4.96 秒。GPU 采样仍约 10–12%，总显存约 1.43 GB，不能声称已充分利用 GPU。
继续依据 `gpu.csv`、`timings.json` 的 action/environment/learning_and_logging 墙钟耗时定位瓶颈；避免为提高利用率盲目加大模型。更多机器人也会增加相机渲染和传输负担。

正式运行不依赖终端存活：用 subprocess.Popen(start_new_session=True) 启动。进程监督器检查日志进展并保存异常状态；每 10000 共享步保存 latest.pt，异常时尽量保存 interrupted.pt。
恢复只承诺权重续训，Godot 世界/随机状态/资格迹/短期记忆未完整保存。使用新目录、保留原始状态文件，记录累计训练步及已完成阶段；不得假称精确恢复世界。

## 第二轮：更新幅度与资格迹

三种子验证已完成，见 VALIDATION01_REPORT.md、validation01_results.json。首轮优势未复现，保留记忆并未稳定优于清空记忆或随机。48个机器人冻结权重逐参数核验通过。验证总耗时2.31小时，GPU平均10.6%。

第二轮 `round02.json` 保持96输入、256宽、3层、相机160×150及60绿/200红，16机器人同场。12学习机器人为6组更新设置×有/无256维FC1记忆，另有上一轮记忆候选冻结、旧冻结、两随机参照。
更新设置：(actor_kappa,critic_kappa,trace_steps)=(3,2,0)、(.3,.2,0)、(.03,.02,0)、(.03,.02,20)、(.03,2,0)、(.03,.02,100)。较小kappa放宽ObGD更新上限，不是直接保证实际更新按固定倍数增加。测试10/100倍上限和只放大actor，区分actor/critic及资格迹的影响。未修改身体信号目标、环境奖励或诊断标签用途。
所有无记忆组从第一轮 ff_96_w256_d3/trained.pt 继承；所有记忆组从 m256_trace0/trained.pt 继承。每类组起点权重相同，但出生位置/随机动作不同。新世界种子53，初始5000冻结步、追加50000学习步、最终50000冻结步。仍为每配置单训练种子；显著结果需再复核。
本轮不做模型扩容；主要诊断是策略仍近均匀、actor有效学习率约1e-5至1e-4。若更强更新仅产生固定动作偏好而无视觉依赖、生存优势，不能判作学会导航。后续应检查冻结视觉遮挡/记忆消融，或更改在线学习机制，而非继续盲目增加网络。

## 第三轮：课程与身体目标

第二轮已完成，报告在 runs/survival_search_round02_20260930/REPORT.md。m256_k003_t20 死亡6次（随机各29次），但97.1%步不加速、只获取1绿块，最长20508步；尚未达长生存/补给目标。不对这种策略直接开展昂贵三种子成功验证。

第三轮 round03.json：固定96/256/3，10学习机器人=5条件×有/无256维FC1记忆。条件为 (gamma,energy_delta,trace_steps)=(.999,0,20)、(.9999,0,20)、(.999,1,20)、(.9999,1,20)、(.9999,1,0)，更新kappa=.03/.02。从首轮同类近均匀权重分支，显式transfer_objective允许更改gamma及HP目标系数；不是精确续训第二轮。每组独立状态，方块数量/位置/颜色事件标签不进入策略或学习。
新增 body_signal 的 energy_delta 默认0，实验值1时附加 (max(next_HP,0)-HP)/5；终止 next_HP 视为0，避免重生HP构造奖励。该项是新的身体维持目标，不宣称仅为不改变最优策略的potential shaping。正负HP变化对称，死亡罚则和既有势函数保留。
同场6参照：第二轮少加速策略冻结、旧冻结、2纯随机、2静止动作（前/侧/转向均neutral，不开火；仍受真实物理与被动耗能影响）。静止参照不调用策略、不更新参数。
世界种子61，课程环境120绿/80红，提供更多补给接触机会。初始5000冻结步、50000学习步、50000冻结步，各阶段HP6起步。该难度不能与原60绿/200红直接比较，任何有希望的模型必须回原难度并做多种子/视觉消融验证。若随机也长存，不判成功。正式开启前小规模同场检查及目标/checkpoint测试通过。
